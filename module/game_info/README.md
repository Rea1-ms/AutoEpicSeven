# 游戏资料维护

活动、通行证和暗影情报等会随版本变化的信息，统一写在 data.yaml（共享游戏资料）里。改完后，任务下次查询就能读到新内容，甘特图也从这里生成。

这里保存游戏规则与时间。账号当前等级、是否领取、上次检查时间仍由各任务识别并保存。改资料不会清空进度，也不会替用户开启任务。

## 参考出处

本模块参考 MAA（明日方舟助手）的资料与执行分离方式，访问日期为2026年9月18日：

- [官方配置文档](https://docs.maa.plus/zh-cn/manual/cli/config.html)：OnSideStory（活动开放条件）读取活动资料，并按客户端判断当前活动。
- [官方使用文档](https://docs.maa.plus/zh-cn/manual/cli/usage.html)：maa activity（活动查询命令）与 maa hot-update（资源更新命令）提供独立于具体任务的资料查询和更新入口。

本项目重新实现了自己的资料格式和查询代码，没有复制 MAA（明日方舟助手）的源码或游戏数据。目前资料随仓库更新发布，运行中的进程会在下次查询时重新读取本地文件；尚未建立独立远程资料服务，也不会访问明日方舟的数据接口。

## 怎么分工

data.yaml（共享游戏资料）描述事实，catalog.py（资料读取与校验）提供查询。它们不导入任务、不操作模拟器、不写账号记录。

context.py（服务器适配）把脚本配置中的服务器转换成资料查询参数。活动、竞技场和暗影情报分别调用查询接口，再按照各自流程操作。timeline.py（时间图）也是资料的读取方，不从任务反向取数据。

当前已经接入：

| 类别 | 使用方式 |
| --- | --- |
| free_gacha_20（每日20抽） | 活动入口按时间执行原领取流程，原活动标识及领取记录保持有效 |
| arena_pass（竞技场通行证） | 查询等级上限；旧满级记录跨越已知赛季边界时，下次进入竞技场重新检查 |
| shadow_commission（暗影情报委托） | 战斗入口和数据更新任务共用等级上限，识别后保存实际等级与当时上限 |

竞技场的赛季日期未知时，仍使用原来周四11点复查的规则。填写新赛季会让旧满级判断失效，但不会主动启动竞技场任务或保证恰好在开季时进入游戏。暗影情报沿用已有采集时机，不新增页面访问。

## 后续更新方法

1. 先核对游戏公告或游戏内时间，在 source（资料来源）写下公告链接或核对记录。所有日期都带时区，推荐北京时间 +08:00（东八区）。
2. 在 events（时段记录）追加新一期，使用新的 id（活动标识）。历史记录保留，时间区间包含开始、不包含结束，相邻两期可以共用交接时刻。
3. 填写 kind（资料类别）、name（显示名称）、服务器起止时间。等级上限有变化时放在本期 values（规则值）中，不修改已结束赛季的记录。
4. 运行下面的校验和查询命令，检查国服与国际服。通过后随资料提交发布。只改本文件不用运行用户配置生成器，也不需要修改任务代码。

本目录不是用户设置：defaults（默认规则）中的38级、30级来自迁移前实现。当前没有已确认的通行证与暗影情报赛季日期，后续核实后再追加，不能用假日期占位。

## 字段约定

| 字段 | 含义 |
| --- | --- |
| schema_version（格式版本） | 当前为1；不认识的版本会报错 |
| defaults（默认规则） | 没有当前时段时使用的规则，按类别填写，必须注明来源 |
| cn_delay_days（国服顺延天数） | 按类别单独配置；目前只为每日20抽设置21天 |
| events（时段记录） | 各期活动或赛季的列表 |
| id（活动标识） | 全局唯一，只用小写英文字母、数字和下划线，以字母开头 |
| kind（资料类别） | 同一玩法保持一致；新增类别可以只用于查询和展示 |
| source（资料来源） | 公告链接、截图核对说明或既有实现的出处 |
| oversea_start / oversea_end（国际服开始／结束） | 同时填写；也可以完全不填，只记录国服 |
| cn_start / cn_end（国服开始／结束） | 覆盖推算时间；未配置该类别顺延时，国服必须完整填写 |
| values（规则值） | 本期共同规则，例如 max_level（等级上限）；可用字符串、整数、布尔值 |
| cn_values（国服规则覆盖） | 国服与国际服不同时填写，只覆盖指定字段 |

同类记录在同一服务器不能重叠。未配置顺延的类别不会自动复制到国服。推算日期会在查询结果与甘特图中标记，仍需以游戏画面确认可操作状态。

下面仅演示格式，日期与等级均为虚构，不要直接放入正式资料：

```yaml
# 加入 events（时段记录）列表；以下数据仅作格式示例。
- id: arena_pass_example_2030_01
  kind: arena_pass
  name: 示例竞技场通行证
  source: '此处替换为已核实的公告链接和维护日期'
  oversea_start: '2030-01-01T11:00:00+08:00'
  oversea_end: '2030-02-01T11:00:00+08:00'
  cn_start: '2030-01-22T11:00:00+08:00'
  cn_end: '2030-02-22T11:00:00+08:00'
  values:
    max_level: 40  # max_level（等级上限），这里只是演示。
```

## 校验与查看

在仓库根目录运行，命令不连接模拟器，也不修改账号记录：

```powershell
# validate（校验）：检查格式、重复字段、时间重叠、等级上限等。
.venv/Scripts/python.exe -B -m module.game_info validate
# current（当前资料）：分别检查 CN（国服）和 OVERSEA（国际服）。
.venv/Scripts/python.exe -B -m module.game_info current --server CN
.venv/Scripts/python.exe -B -m module.game_info current --server OVERSEA
# --at（指定时刻）：检查换季时刻，日期只是查询示例。
.venv/Scripts/python.exe -B -m module.game_info current --server CN --at '2030-01-22T11:00:00+08:00'
# timeline（时间图）：输出完整甘特图与表格。
.venv/Scripts/python.exe -B -m module.game_info timeline
```

--path（指定文件）可用于校验尚未发布的资料副本，例如在校验命令后追加 `--path '待检查资料.yaml'`（读取指定副本）。命令出错时返回非零状态。运行时读到损坏或不支持的资料也会明确报错，不会当成“当前没有活动”。

tasks/activity/calendar.md（活动时间图）是展示快照，修改资料后可用上述时间图命令重新生成。任务读取的是原始资料，不读取这份快照。旧的 `python -m tasks.activity.calendar`（活动时间图命令）仍可使用。

## 新增读取方

任务通过 load_info（读取资料）取得不可变快照，调用 current（查询当前时段）、level_cap（查询等级上限）或 next_change（查询下一次边界）。查询需要类别和服务器，资料模块不依赖任务是否实现或语言素材是否齐全。

资料中只增加类别不会增加自动操作。新玩法需要在自己的任务中实现页面识别和动作，再接入查询；不要在资料里写函数名、执行命令或任务调用。

每次查询读取当前文件内容，已解析内容会缓存，修改后不需要重启进程。一次操作可以复用同一个快照，避免执行途中混用两版资料。若以后独立发布远程资料，下载、校验和替换本地文件应放在单独更新器中，现有任务仍只依赖查询接口。

## 验证范围

离线测试放在主检出目录已忽略的 test（测试）目录：test_game_info.py（资料及读取方测试）、test_cn_september_update.py（活动与分服回归）和 test_special_activity_config.py（配置升级回归）。覆盖分服日期、顺延例外、边界切换、上限变化、资料替换、错误格式与原活动领取记录。复查账号记录时，资料变化只会影响后续识别与复查条件，不会把当前等级猜测为0。
