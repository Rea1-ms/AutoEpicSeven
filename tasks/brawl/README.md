# 大乱斗

当前可以离线分析国际服中文截图，并根据明确提供的完整名单推荐阵容。已补上开局、整局结算、单英雄结果、候补逐人扫描、五名英雄的场上外观、选格与单次上场确认、满员换人、单次下场识名、传送报价、缘分召唤、单次升级确认和两倍速控制；还不能自动打完整局，也没有接入任务菜单和调度。

规则来自根目录的大乱斗攻略.md。34名英雄的阵营、职业、射程、解锁等级、已知技能刻印要求，以及升级费用、召唤消耗、羁绊和传送收益已经整理为独立规则。露斌作为露彬的别名处理。普通召唤只记录8级和9级概率，其他等级保留未知；缘分召唤使用攻略中的固定概率。

截图分析区分一般和挑战模式，识别准备、升级确认、英雄获得、战斗、单轮胜负、布阵选格、传送选择、概率说明、放弃确认、活动大厅与整局胜负结算。局外总等级提升和英雄解锁说明单独处理。只有准备画面的资源与人数均识别可靠时，才输出可负担的召唤和升级选项。这些是资源判断，不代表已经消费或建议连续召唤。遮挡、选格和识别不完整时不推算余额，也不根据一次点击更新状态。

英雄结果页读取单个英雄名、当前刻印和有明确箭头时的原刻印。长名称按阅读顺序合并，刻印用真实模板校验完整字形，满刻印自动传送不会被当成刻印下降。没有前后对照时，原刻印保持未知；识别不完整时不补默认值。该结果不代表完整阵容，重复截图也不累计获得次数。

单轮成功和失败都会自动跳转，不需要确认；可以直接从战斗进入下一个稳定准备页。失败后可能重试同一轮，金币、生命和候补却已经变化，因此既不依赖闪现动画计数，也不把回合号当作一次战斗的唯一标记。只有明确的整局结算文字和返回按钮同时出现，才报告整局结束。

两倍速控制只在稳定准备或战斗画面确认一倍速后点击，按3秒间隔重试，后续截图确认两倍速才算成功。遮挡或未知速度不点击，单轮过渡和结算交回调用方处理。独立调用的局部等待最多10秒，不限制整场战斗；超时和页面变化均不能当作成功。目前该行为通过模拟设备回放验证，尚未接入整局入口或实机运行。

单次升级由调用方明确选择时机与硬币预留。先保存完整准备状态，再核对确认页的前后等级、人数上限、费用和当前余额；入口按3秒间隔重试，付款按钮只点一次。返回准备页后，只有同一回合、模式、上场人数和代币余额不变，等级及上限增加1、硬币按报价减少，才确认成功。动画、旧余额或暂时读不清时只等待；确认页重新出现、其他场景或局部超时不会再次付款。已有第8轮4级到5级的实际截图，硬币205变105；重复帧、时间和点击为明确模拟，其他升级档位还没有完整实图回放。离线报告新增升级报价，仍不声称执行或完成了升级。

候补读取右侧完整可见的姓名和刻印，边缘残字及选中卡片遮住的相邻条目不猜。刻印读不清保留未知，加号只标明当前控件位置，不能证明还有上场名额。克莉丝缇的末字在当前文字模型中容易漏读，改用完整姓名实图核对，不把三个残字当成通用别名。有序重叠的多帧仍只作局部合并；旧帧坐标不进入结果。

候补扫描先大幅向下滑回顶部，再按3秒间隔逐个点选下方相邻卡片。每次用原相邻头像和新选中头像核对，避免跳过被大卡遮住姓名的人物。顶部和底部都需要对应背景或空候补提示的正面证据，重复画面、读不到姓名和达到动作上限均不代表到底。只点击一次下一人，未确认便等待，局部超时返回不完整；回合、模式、等级、人数、余额、已知刻印或可见队列变化时停止。当前端点素材对应这批截图的场景，其他背景保持未知。

用户确认候补固定10人，与场上名额独立：4级可上5人并留10名候补，共15人；9级最多20人。完整人工名单按当前实际上场人数加10校验，阵容推荐按等级最大上场人数加10校验。扫描到第10人仍须确认底部；若还有下一张卡则报告容量矛盾，不再点击。只有完整候补扫描才计算剩余空位，局部名单不推算。候补满时不能直接下场，可以通过换人查看姓名；识别身份不使用传送删除。直接下场已有三张连续图和独立单次接口，仍要求调用方先提供完整候补扫描。

扫描完成只证明候补完整。只有同一准备页明确显示场上0人时，才同时具备完整英雄名单；有场上人物时仍需另外识别。单张分析报告会显示当前选中人物、端点和相邻目标，但不能单凭这些生成完整阵容。连续图原本从下向上选择，回归将稳定画面反向排列并加入重复帧，模拟从上向下的操作响应；这不是实际设备执行记录。

点击候补加号或场上人物后，选格页可以定位28格，按屏幕上的7行、每行4格记录。补图确认蓝色双箭头是已有人的换位目标，可以同时出现多个；绿色选中格旁的放大镜才用于定位当前人物。此前把蓝色标记解释为源格有误，现已修正。先逐格核对边框，动画或遮挡不能生成未确认的目标；没有标记也不代表空格。绿色来源与右侧候补所选人物互相独立，不能将右侧姓名套给场上人物。

场上读取目前支持格伦、辅助型拉兹、卡琳、战斗型玛雅和小春的已采集待机姿态，输出姓名、外观区域和脚下像素锚点。每个人物均用不同于模板来源的实图核对；其他人物、姿态变化、遮挡或重复匹配保持未知。新图中小春换人后的部分待机姿态仍不能匹配，等待可靠画面，不降低识别门槛。刻印暂不识别，不能把模板来源中的刻印沿用到当前英雄。识别到所有姓名也不代表已获得可用于策略的完整属性。

头顶羁绊另行读取阵营与职业，不依赖人物身体的当前姿态。规则表中21名英雄可由这两个字段唯一确定；其余13名分属6组相同组合，保留全部候选。例如夏日假期与盗贼仍可能是赛兹或卡琳，不能按候选顺序选第一名。当前图标素材覆盖卡厄思、人造生命体、转职、夏日假期4种阵营和除精灵师外的5种职业，规则表的21人不等于已实现21人的实图识别。图标被遮挡、缺少一个字段或两枚图标无法配对时保持未知。头标区域不是脚下格位，因此身份读出后也不能直接用头标坐标点击交换格；原有外观定位仍负责已支持人物的动作确认。

截图中的透明图标已经与场景合成，没有原始透明通道。匹配时从模板提取亮色笔画和紧邻的暗轮廓，排除已核对的背景空隙，并去掉与裁片边缘连通的场景亮斑，减少头发、衣服和地面的影响；还要核对笔画亮度与轮廓明暗，避免纯色块被当作图标。这是已采集图标的有效像素范围，不是恢复原始透明图。人物遮住实际笔画或背景严重破坏对比时仍保持未知，不能按上一帧补全。小春的多张不同待机姿态已经可以独立读取同一组头顶羁绊。

单次上场要求调用方已经选好支持识别的候补英雄，并明确提供屏幕行列。先确认当前还有上场名额，点击加号后核对完整网格、已上场人数与蓝色目标数量一致，再点有黄色边框的目标格。两步动作间隔3秒；目标格只点一次，等待返回准备页、人数增加1且对应人物出现在目标位置，才确认完成。余额、回合、模式、刻印或所选人物变化时停止；遮挡和无响应不算成功。没有把策略逻辑格映射到屏幕格。

新增满员单次换人，调用方先选择候补并提供屏幕行列。换人前分别确认候补身份和目标格的场上外观；打开选格后，正面识别全部已占交换按钮，其数量须与上场人数一致。10/10画面隐藏空格边框，使用本帧已占格锚点读取交换目标，不能生成空位。目标只点击一次，返回准备页后要求回合、模式、人数和两种余额不变，且目标位置出现所选英雄。新图确认小春换入右下角后，候补焦点自动变为卡琳；焦点不能证明卡琳上场。场上刻印和完整候补仍保持未知。

需要查明未知人物时，调用方可以明确使用识名换人：先取得完整候补名单，再选择能确认上场位置的英雄与目标格。入口核对当前可见候补与完整名单一致，选格页确认目标已有人，交换后确认换入人物实际站到该格。之后重新完整扫描候补，只有原名单恰好减少换入者、增加一名人物，其他姓名与刻印均不变，才认定新增者就是换出的英雄。两次扫描的回合、模式、人数和余额也须一致；局部列表、自动焦点、旧截图和一次点击均不能证明身份。满10人候补也能使用交换，直接下场则必须有空位。这是独立的单次接口，扫描与交换尚未接入整局自动流程。

单次下场要求完整候补名单证明至少有一个空位，并与当前可见姓名、刻印和准备状态一致。调用方明确指定屏幕格子后，只点击一次选中；也可从已经核实的选格页开始。选格本身不证明那里有人，必须看到该格的绿色来源标记与对应红色减号，才点击一次下场。返回准备页后，人数精确减少1、其余状态与两种余额不变，并出现原完整候补名单中没有的新姓名和刻印，才确认该人物下场。原候补刻印冲突或新增多人会停止，未看到新增姓名只等待，不重按减号。人物待机姿态未知不阻止先选格确认，但不根据头标推算脚下位置。新图确认小春回候补，人数10变9、余额仍90与4，焦点仍为利纳柯；未把焦点当作下场身份。完整候补扫描和单次动作尚未自动串联，新增卡片在屏幕外时仍需后续扫描处理。

传送栏分别读取当前余额、所选状态和两种货币报价。英雄移到左栏时便从候补消失，只有确认后返回准备页且余额按报价增加，才判定完成。确认动作要求调用方先确定所选英雄，并保存完整左栏的当前图像与报价；变化时停止，按3秒间隔重试，最多等待10秒。返回准备页后即使余额尚未刷新，也不会再次确认。新图三人报价依次为3与2、8与7、11与9，确认后余额37与0变48与9；多位数会带动硬币图标左移，数字区域改按当前图标定位，原单人样本仍须通过。传送页点击右侧人物会直接选入左栏，候补扫描仅在准备页运行，不能移用到传送页。左栏动画可能导致保守退出；尚未自动选择或分批传送。传送后若出现英雄结果，保留该画面交回调用方，不能当成付费召唤，也不猜赠送原因和额外收益。

新增下级、上级缘分召唤的单次动作，由调用方明确选择种类和代币预留。只在稳定准备页核对完整面板与可用按钮后付款一次，读到本次结果及准确扣款才按3秒间隔关闭结果，返回同一准备上下文再次核对余额后确认完成。新图下级获得维多丽卡C，硬币90不变、代币54变44；上级将黎洁特S升至SS，代币44变4。重复准备页、结果未知或余额延迟不能再次付款；无本次付款的英雄页、额外不同英雄和满刻印溢出交回调用方处理，不累计完整阵容。传送返回48与9到召唤开始90与54之间有未拍操作，不能作为同一连续收益记录。这些动作仍只做离线模拟验证，未接入自动选人、连续召唤或整局入口。

## 使用

从仓库根目录使用已有项目解释器运行 `python -B -m tasks.brawl.brawl --image "截图.png" --out ".cache/brawl-report.json"`（分析截图并保存新报告）。图像必须是1280×720；输出文件已存在时拒绝覆盖。该命令只读截图，不读取账号配置或连接模拟器。

当前使用本工作树已有的项目解释器，业务代码与正式样本均从当前工作树读取，没有安装或升级依赖。

可选参数 `--roster`（完整阵容资料路径）读取结构化文本。必须明确填写 `complete`（完整标记，值为真）、`round_number`（截图回合）、`level`（截图等级）、`heroes`（场上和等待队列的完整英雄列表）及 `class_bonuses`（职业天赋加成）。每名英雄填写 `name`（英雄名）和 `imprint`（刻印）；白板写 `NONE`（无刻印），不能省略。职业天赋用职业中文名和0或1填写，没有加成时明确给空字典。

名单来自人工提供，不能当作已经完成图像识别。回合与等级不符、缺少刻印、重复英雄，或名单超出当前上场人数至上场人数加10的范围时拒绝推荐；同回合手动召唤、布阵或传送后，也需要重新填写。战后可能赠送英雄，因此旧回合名单不沿用。

## 阵容建议

阵容按完整队伍评分，计算实际达到的羁绊档位，同时考虑稀有度、刻印、已解锁的大招和近远程搭配。职业天赋单独传入，不默认全部加一。评分权重是初版经验选择，没有用实战胜率校准；小名单枚举组合，大名单保留有限候选，不宣称战斗最优解。

站位只给4×7交错棋盘的逻辑格，行0表示靠近敌人的一排。近战优先前排，远程优先后排；黎洁特射程3、露彬射程1、莱娅射程2单独处理。莱娅优先第二排是当前策略选择，不代表游戏强制站位。尚未根据实际敌方阵容、女仆聚光灯或攻击力最高目标调整，也没有把逻辑格映射为屏幕点击坐标。

传送收益按本局实际取得份数和局外是否拥有计算，不能只看当前刻印。已满刻印后的新重复英雄按白板自动传送。攻略里连续两条同名刻印的例子保留为原始记录，不推断第二条是哪一档。

参考自走棋项目只用于理解按人数选阵容、整队羁绊评分和前后排安排，代码独立实现。没有沿用其他游戏的利息、商店刷新、三合一或点击后直接扣余额的做法。

## 待补的实际流程

目前已核对196张截图，包括25张焦点、满员换人、多人传送及缘分召唤图，以及补充的传送赠送英雄结果和三张直接下场图；已有一般与挑战模式的第1轮开局、一般模式冠军、两种模式失败结算、总等级提升和英雄解锁。两张开局均为天赋影响后的2级、0/3、70硬币，不能据此推定所有账号初始都是2级。挑战模式冠军尚无实图覆盖，但不作为继续开发的前置条件。

完整自动对局还需要补齐其他场上人物与刻印、策略位置与屏幕格子的对应，以及整队交换和移动后的验证。新增空场截图中六种职业计数均为1，可作为当前账号六职业各加一的人工依据，暂不需要重复补攻略中的天赋效果描述；尚未自动读取天赋，也不能把这个账号的结果设为所有账号的默认值。单个英雄结果不能恢复完整名单。传送只实现已选批次的确认，没有按阵容自动选择英雄；整队布阵、开战入口和整体调度仍未建立。

下级、上级召唤、满员换人和直接下场均已有完整前后图，不再重复要求。补充图确认赠送结果为黎洁特从A升至S，后续准备页已有90硬币和54代币；赠送来源由用户说明确认，结果画面本身不区分付费与赠送，也不推算中间未拍操作的收益或赠送次数。直接下场三步连续图已补齐。已有开局、整局结算、召唤、赠送结果与天赋说明不用重复提供，挑战模式冠军仍可后补。

正式离线用例归入 `brawl`（大乱斗测试集），通过项目统一测试入口先列出再运行。精选脱敏样本和制作配方保存在正式样本目录；手动采样、分析报告与测试缓存保留在忽略目录，可手动清理。
