活动时间统一写在 calendar.yaml（活动日历）里，任务和甘特图读取同一份数据。

国际服有新活动时，增加一条记录并填写起止时间。国服默认顺延21天，维护时间有差异时才填写国服覆盖时间。旧记录保留，到期后自动跳过；相邻活动在交接时间自动切换。不同流程可同时执行，同一流程的两期活动不能重叠，避免把一次领取算作两期奖励。

每期活动使用不同的 id（活动标识），领取记录也按活动和服务器分开。mode（流程类型）决定使用哪套已实现的操作；新玩法仍需要补流程和素材，日历只负责时间衔接。

当前20抽活动的国服截止时间按游戏倒计时核对为11月19日11点。国际服开始日期来自8月27日素材版本，开始时刻暂沿用原国际服截止时刻的2点；这段历史时刻不影响当前调度。

运行 `python -m tasks.activity.calendar`（输出活动甘特图）可以查看最新时间表。calendar.md（活动时间图）是本次生成的快照。

旧活动按日期和名称放在 legacy（旧活动归档）目录。2026-06-25 版本的夏日活动实现和调度保存在 summer_2026_06_25（2026年6月25日夏日活动）子目录，素材沿用原有日期目录。当前活动不再因为竞技场或战斗结束而反复调度夏日奖励。

当前特别活动配置只保留“领取每日20抽”。截图和结果识别在“召唤”任务中设置；夏日活动原有的四个奖励选项和任务绑定保存在归档目录的 config.yaml（原配置备份）中。
