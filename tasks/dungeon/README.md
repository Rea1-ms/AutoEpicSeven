# 托管战斗进度

国服和国际服中文共用进度识别区域。准备页已有预计时长时，继续按原来的时间检查；接管手动开启的托管，或预计时间已过但还没结束时，再打开详情读取进度。

- `OCR_SETTLEMENT_PROGRESS`（战斗进度区域）读取已完成场数和总场数。
- `OCR_SETTLEMENT_TIME_SPENT`（已用时间区域）读取时、分、秒，不是剩余时间。
- 剩余时长估算为“已用时间 ÷ 已完成场数 × 未完成场数”，再沿用一分钟检查余量。估算只决定下次检查时间，不表示战斗已经结束。

详情页标题在运行中和结算时相同。出现“中断”才按运行中详情处理：读取后用 `AD_BUFF_X_CLOSE`（广告增益关闭按钮）关闭，并确认回到可识别的页面；不会点击“中断”。真正完成仍走结算、关闭奖励和返回页面的流程。

进度为零、已完成全部场数或已用时间为零时，无法继续推算，保留会话并按一分钟间隔检查。识别失败会短暂重试，之后保留已有有效预计时间；没有有效时间就按一分钟间隔检查。进度读数不会清除会话，也不会改动紧急任务的后续安排。

后续界面变化时，先更新上述两块源图并重新生成素材定义。解析和估算在 `repeat_progress.py`（进度识别实现），打开详情、关闭和调度在 `repeat.py`（托管流程实现）。验证应同时覆盖两服素材、识别失败、零进度、满进度、点击未生效，以及读取途中转入结算；测试仍放主检出目录被忽略的测试文件夹。
