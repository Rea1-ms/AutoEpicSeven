# 依赖安装与维护

先安装 uv（依赖管理工具），再在项目根目录选择对应命令。项目要求 Python 3.10（解释器），安装时会按配置准备解释器和 `.venv/`（虚拟环境）。

| 用途 | 一行安装命令 |
| --- | --- |
| 运行脚本 | `uv sync --locked --no-dev`（按锁文件安装运行依赖） |
| 开发、截图辅助与离线测试 | `uv sync --locked`（按锁文件安装运行和开发依赖） |

两种方式使用同一份 `pyproject.toml`（项目配置）和 `uv.lock`（依赖锁文件）。`--locked`（锁文件一致性检查）会在配置与锁文件不一致时报错；此时应更新锁文件，不能用 `--frozen`（跳过锁文件时效检查）掩盖问题。

## 依赖放在哪里

运行需要的包放在 `[project].dependencies`（运行依赖），仅供开发使用的包放在 `[dependency-groups].dev`（开发依赖组）。开发依赖不放进发布可选依赖。

uv（依赖管理工具）默认包含 `dev`（开发组），因此不需要额外设置默认组。`--only-dev`（仅安装开发组）不包含运行依赖，不能代替完整开发安装命令。

当前开发组提供终端截图热键、测试覆盖率、代码检查、类型检查及旧依赖兼容支持。`pynput`（键盘监听库）只用于终端全局热键，截图图形窗口不依赖它；`setuptools`（包构建与兼容工具）保留现有离线测试需要的旧包兼容能力，调整前应验证相关导入与测试。

## 添加和更新

新增运行依赖用 `uv add --no-sync <包名>`（更新配置和锁文件，不同步现有环境）；新增开发依赖用 `uv add --dev --no-sync <包名>`（更新开发组和锁文件，不同步现有环境）。将占位内容替换为实际包名。

手动修改配置后，执行 `uv lock`（更新锁文件，不安装依赖）。检查差异，确认没有无关的运行依赖升级，再一并提交配置与锁文件。锁文件应保持版本控制；仓库已有通用锁文件忽略规则，因此要保留 `!/uv.lock`（允许跟踪项目锁文件）的例外。

只用 `uv pip install`（临时安装包）不会维护项目依赖声明，不能代替上述步骤。需要实际安装时，再执行对应的一行安装命令。

## 检查与验证

依赖配置变更后，在项目根目录依次执行：

```powershell
uv lock --check
uv sync --locked --no-dev --dry-run
uv sync --locked --dry-run
```

这三项分别检查锁文件一致性、运行安装预演和开发安装预演。`--dry-run`（安装预演）不会实际安装，不能据此宣称新环境已可用或离线回归通过。依赖、测试入口或工作流发生变化时，还需按项目离线规范完成对应验收；只改说明文档无需重跑整套游戏回归。

现有 `requirements-test-pinned.txt`（云端测试锁定清单）和云端工作流继续按各自记录维护；本地依赖分组不代表云端环境已迁移或验证。开发工具入口见 [开发工具说明](../dev_tools/README.md)。
